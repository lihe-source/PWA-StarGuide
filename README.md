# 星空指南針 PWA V1.1.0

免編譯、無後端的靜態 PWA。解壓縮後即可將資料夾內的檔案部署到 GitHub Pages。不需要 API Key、付費辨識服務、Node.js 或資料庫伺服器。

本版已完成程式與程式層測試；尚未完成實際手機瀏覽器畫面、相機／羅盤、真實夜空及真實離線升級驗收。請先依 TESTING.md 在自己的手機試用，不應視為已驗證的專業星圖解算器。

## 1. 部署到 GitHub Pages

1. 建立 GitHub repository，或開啟原本使用的 repository。
2. 將本資料夾「裡面的檔案」上傳到儲存庫根目錄，讓 `index.html` 位於根目錄。不要只上傳 ZIP；也不要在舊站外面再套一層版本資料夾。
3. 保留 `.nojekyll` 與三份第三方授權文件。`test.cjs`、`package.json`、說明文件可一併上傳，不影響使用。
4. 開啟 repository 的 Settings → Pages，Source 選「Deploy from a branch」，選擇存放程式的分支（例如 main）及「/(root)」，儲存。
5. 等待 GitHub 部署完成，使用 Pages 畫面提供的 HTTPS 網址開啟。
6. 更新舊站時，先匯出既有資料，再以新檔案覆蓋同名檔案；保持原網址／路徑不變。不需刪除瀏覽器資料或移除 PWA。

官方說明：[設定 GitHub Pages 發佈來源](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。本程式未替使用者建立或修改任何 GitHub 儲存庫。

## 2. 安裝及首次啟用

- 一般使用者不需安裝開發工具。可直接開網頁，或用瀏覽器「加入主畫面／安裝應用程式」。iPhone 可從 Safari 的分享選單加入主畫面；實際選單依系統版本而異。
- 啟動時會嘗試開啟後置相機；仍須遵守瀏覽器的相機授權。若被拒絕或沒有相機，會回到星盤。
- 點「啟用觀星」取得方向權限與 GPS。iPhone 的方向權限可能需要使用者手勢；無法保證在完全無點擊的情況下啟用羅盤。
- GPS 無法取得時，可在「設定」手動輸入經緯度。不要以假位置代替實際觀測位置。
- 首次需連網載入完整離線資源，之後可離線使用已快取的星盤、星表與照片分析。離線能力仍須在實機確認。
- 不支援從檔案總管直接開 `file://.../index.html`。相機、定位與 Service Worker 需要安全來源；正式使用 HTTPS。

## 3. 主要操作

### 相機觀星

畫面同時顯示 `yy/mm/dd hh:mm`、指南針、鏡頭方位、仰角及方向狀態。時間依裝置當地時區顯示；紀錄另保存 UTC 時間與時區名稱。

相機的星名疊圖是「○ 位置推算」，不是從即時影像確認星名。先平放手機確認北方基準，再舉起對向天空；金屬、磁性手機殼及附近電器可能使羅盤偏移。

在設定選擇後置鏡頭及「目前畫面水平視角」。此視角是經畫面裁切後的水平視角，不是手機規格表的對角視角。更換鏡頭或橫直向後需重新核對。若已知某顆星，可搜尋、選取，在相機準星對準實際星體後按「準星對準後校正」。請只用確定認識的星校正，並再核對其他星。

北方基準修正預設 0。只有確定感測器輸出磁北時，才輸入當地磁偏角（東偏為正），避免對已是真北的資料重複修正。相對方向感測器的星體校正只在本次執行中有效。

### 全天星盤

- 天頂在中央、地平線在外圈；仰視天空，所以東方在左、西方在右。
- 單指拖曳全景可旋轉；雙指或「＋／−」縮放。放大後拖曳可平移；「全景」恢復初始視圖。
- 可切換北方固定／隨鏡頭方向；後者需要有效方向資料。
- 點星體看方位、仰角、星等；搜尋支援已收錄的中文星名、英文星名、星座名稱及 HIP 編號。
- 支援 5,070 顆六等及更亮恆星、月球及七顆其他行星；不是全部恆星，也不含太陽觀測、衛星、彗星或深空星雲。
- 提供星座連線／名稱、方位格線、三段星等限制、紅色夜間模式、省電模式。星點大小與月球符號為示意，非真實視直徑。
- 「圖層／時間」可預覽 1900–2100 年。進入相機會自動回到即時時間，避免以預覽時間拍攝。

### 拍照與配對

按快門的同一個同步步驟即保存時間、位置、姿態、視角及影像畫面，再進行非同步分析，避免分析完成時的方向污染拍攝資料。

辨識採「已知拍攝方向附近的星群幾何比對」，並非任意照片的全天盲解。候選亮點會經過亮度門檻、連通區與形狀篩選；比對使用小範圍平移、旋轉及縮放的 RANSAC。

通過條件至少六個一對一星點、足夠的二維分布、一致的小幾何殘差；高密度影像還需配對到較高比例的星點，多解時拒絕。即使顯示「● 多星配對通過」，也只代表本演算法的條件通過，不等於經專業天文定位驗證的絕對星名。

- ○ 位置推算：依位置、時間及方向推算的星表位置。
- ◇ 候選星點：影像中有亮點，但不足以確定星名。
- ● 多星配對通過：幾何配對通過，顯示配對星名。

照片太暗、失焦、晃動、光害、雲層、鏡頭畸變或方向不準時，可能完全配對不到。一般手機網頁相機通常無法保證長曝光能力；可先用原生相機夜景模式拍照，再匯入。不要將鏡頭對準太陽來測試。

拍攝影像按目前預覽畫面裁切，長邊最多 1,600 px；另存無標籤圖及標示圖，不是原生相機完整感光元件的 RAW 檔。分析長邊最多 960 px；殘差單位為該分析尺寸的像素。

### 照片匯入

支援 JPEG、PNG、WebP，每張最多 25 MB／解碼後最多 8,000 萬像素。HEIC 請先轉成 JPEG。保留匯入檔案原始位元組，另產生縮小的標示圖。

JPEG 會嘗試讀取 EXIF 拍攝時間、GPS、真北方向。缺少時間時不會用檔案修改時間假充拍攝時間；必須自行補入。EXIF 時間以裝置當地時區解讀，跨時區照片需換算。方位、仰角、照片水平視角與畫面傾斜角需核對；方向未知可留空，仍可保存原圖，但不做星名配對。不要以手機目前姿態代替舊照片拍攝姿態。

分析時可取消；已取得的原圖仍保存為未完成配對的紀錄。從紀錄重新分析會建立新紀錄，不覆蓋舊紀錄。

## 4. 儲存、舊版遷移及備份

- 照片放在 IndexedDB，設定在 localStorage。資料依網站來源與路徑隔離；換網域／路徑可能看到新的空資料庫。
- 紀錄依拍攝時間排序，每頁 20 筆，縮圖獨立儲存，列表不一次讀取所有原圖。
- 第一次啟動會嘗試從同來源 V1.0.0 的 `StarGuideDB` 複製紀錄；不刪除原資料。舊版只有已標示的合成照片，無法還原當時未保存的原圖；舊配對不會自動視為新版驗證成功。
- 「紀錄 → 匯出備份」包含照片與設定；「設定 → 匯出設定」只備份設定。備份包含照片及精確位置，請自行保管。
- 匯入備份先驗證格式，再逐筆合併；相同 ID 不覆寫。若中途儲存空間不足，可能已成功匯入部分紀錄，釋放空間後可重試，已匯入的 ID 會跳過。
- 備份原圖與標示圖合計限制約 120 MB，匯入 JSON 限 180 MB；大量資料請定期分批整理。
- 瀏覽器可能清理資料，保留儲存空間的請求不保證核准。清除網站資料或刪除紀錄不能由程式自行復原，務必定期備份。

## 5. 更新策略

啟動、回到頁面及手動檢查時讀取不快取的版本資訊。離線或讀取失敗會顯示無法確認，不宣稱是最新版本。新 Service Worker 先確認版本並下載完整資源；操作、編輯及對話框結束後再切換，不以固定秒數強制重整。跨分頁更新也會讓忙碌頁面等到操作完成後再重新載入。

JavaScript、CSS 與 Worker 使用版本查詢參數，降低 V1.0.0 舊快取混入新版的風險；新 Worker 亦接受舊版更新訊息。若升級畫面仍停留舊版，先備份，關閉所有該網站頁面與 PWA，再重新開啟。不要先刪除網站資料。

開發後續版本時須一起調整 `app.js`、`sw.js`、`version.json`、`index.html`、`worker.js` 中的版本，並完整部署所有檔案。不要只替換 HTML。

## 6. 開發及測試

正式部署與一般使用均免安裝套件。若開發者要在電腦本機預覽，可在此資料夾執行 `python3 -m http.server 8080`，再開 `http://localhost:8080/`。此網址僅指該電腦本身；手機不能以一般 HTTP 的電腦區網 IP 當作正式相機測試環境，建議使用 GitHub Pages HTTPS。

若要重跑程式層測試，需要 Node.js 20+：執行 `npm install`，再 `npm test`。測試相依套件只供開發使用，不是網站執行需求。詳細結果與手機驗收步驟見 TESTING.md。

檔案分工：`app.js` 介面及流程、`core.js` 天文投影及比對、`worker.js` 星點提取、`storage.js` 資料管理、`exif.js` 照片中繼資料、`sw.js` 離線更新。第三方程式及星表來源見 THIRD-PARTY.md。
